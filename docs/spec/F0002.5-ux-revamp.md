## Motivação

A interface atual ("feita à mão" com Tailwind puro) está pouco amigável e pouco
intuitiva, e cada nova feature recria os mesmos padrões de formulário/lista do zero —
violando DRY e acumulando dívida visual. Antes de F0003 em diante, vale investir em:

1. **Usabilidade**: mais texto explicativo (helper text, descrições, empty states,
   placeholders) em cada parte, para o usuário entender o que fazer sem tutorial.
2. **DRY**: componentes prontos e reusáveis em vez de reinventar a roda a cada tela.
3. **Performance e código limpo**: gestão de dados/cache padronizada no client.

## Decisões de Stack (fundação)

Adições à Golden Stack (todas **estáveis**, ver `README.md` e `docs/03`):

- **shadcn/ui** — componentes copiados para o repo (não é dependência versionada; gerada
  via CLI sobre **Radix UI** + `class-variance-authority` + `tailwind-merge` + `clsx`).
  Ícones via **lucide-react**. Evita reinventar Button/Input/Select/Dialog/Table/Form/Toast/Tabs/Card.
- **react-hook-form** + **@hookform/resolvers** (resolver **Zod**) — formulários DRY que
  reusam os mesmos schemas Zod da validação de API.
- **@tanstack/react-query** — fetch/cache/estados/invalidação no client (substitui `useEffect`+`fetch`).
- **@tanstack/react-table** — tabelas/listas headless estilizadas com shadcn.
- **react-imask** — máscaras de input (telefone/CPF/CNPJ/CEP/moeda), integrável ao RHF.

Princípio: **shadcn = não inventar a roda**; **react-hook-form/Zod = formulários DRY**;
**TanStack = dados/listas com menos código e melhor performance**.

## Escopo

**Inclui:**

1. **Setup da fundação**: shadcn/ui (tokens do `docs/10` → CSS variables), react-hook-form +
   Zod resolver, TanStack Query (provider global) + Table, lucide-react, react-imask.
2. **Primitivos compartilhados (DRY)** — base reusada por F0002.6/2.7 e adiante:
   - `MaskedInput` (telefone/CPF/CNPJ/CEP/moeda) integrável ao RHF.
   - `PessoaTipoField` — switch **PF/PJ** + documento (troca máscara/validação). **Nunca** campo único CPF/CNPJ.
   - `JargonLabel` — label + ícone `ⓘ` (Tooltip) para termos do produto.
   - Estados `LoadingState` (skeleton), `EmptyState` (msg + CTA), `ErrorState` (retry).
   - Glossário de **copy de jargão** centralizado.
3. **Refactor das telas já em produção** para a nova fundação, **sem mudar comportamento**:
   - **Login** (`/login`) — componentes shadcn, mantendo o Split Layout.
   - **Profissionais** — lista (TanStack Query + Table + estados) e formulário (RHF + Zod + shadcn, máscara/PF-PJ no override de billing).
   - **App Shell** — shadcn + ícones lucide-react, mantendo o padrão de `docs/10`.

**Não inclui** (movido para as fases fatiadas): onboarding (F0002.6), Configurações/Meio de
Pagamento e tutorial Asaas (F0002.7), quadro de planos (F0011), Financeiro (F0013). Nenhuma
nova regra de negócio, rota de API ou mudança de modelo nesta fase.

## UX (sobre `docs/10`)

A fundação (tokens, Split Layout, App Shell, padrões globais loading/empty/error, validação
inline, tooltips, máscaras, PF/PJ, ícones) vive em **[`docs/10-design-system.md`](../10-design-system.md)**.
Diretrizes desta fase:

- **Mais texto, menos adivinhação**: todo formulário tem subtítulo de contexto; todo campo
  não óbvio tem helper text; toda lista vazia tem mensagem + CTA.
- **Consistência**: um único `Form`, `Button`, `Input`, `Select`, `Dialog`, `Table`, `Toast`,
  `Tooltip` (shadcn) em todo o app — sem variações ad-hoc.
- **Fidelidade ao que existe**: o refactor **mantém** os layouts já especificados; troca a
  implementação por componentes shadcn, não o padrão de tela nem o comportamento.

## Verificação

- **Local (Jest — integração)**: a suíte existente (rotas/API) continua **verde** — refactor é de
  apresentação e não muda contratos.
- **Local (Jest — componente/render, RTL + `jsdom`)**: **obrigatório** para as telas refatoradas —
  `ProfessionalForm`, `PessoaTipoField`, `MaskedInput`, `JargonLabel` e os estados. Os testes devem
  **montar sem lançar** e **exercitar os ramos interativos**: em `ProfessionalForm`, alternar
  "faturamento próprio" (revela token/NFS-e/CPF-CNPJ) e trocar **PF↔PJ** (a máscara muda). Este é o
  buraco que deixou passar o crash `useFormField should be used within <FormField>` — ver Política de
  Testes em `docs/07` §4.1.
- **Stage/Prod (Cypress)**: smokes públicos F0000/F0001/F0002 verdes (status/redirect/401).
  Fluxos autenticados validados manualmente no gate humano.
- **Guardrails**: gating de módulos, isolamento por `businessId` e resolução de billing
  permanecem intactos (sem mudança de backend nesta fase).
